
# Docker — Core Concepts

## 1. What is Docker
- Docker is a containerization platform for building, packaging, and running applications.
- A container is a lightweight, isolated runtime environment bundling:
  - Application code
  - Runtime
  - System libraries
  - Dependencies
- Containers share the host OS kernel instead of virtualizing a full OS.
- Compared to virtual machines:
  - Faster startup time
  - Lower resource overhead
  - Higher deployment density

## 2. Docker Image
- A Docker Image is a read-only template used to create containers.
- It packages:
  - Application code
  - Runtime
  - Libraries
  - Configuration
- Images are built using a Dockerfile.
- A Dockerfile defines step-by-step build instructions:
  - Specify base image
  - Copy source files
  - Install dependencies
  - Set environment variables
  - Define entrypoint

### Image Layering
- Docker images use a layered filesystem.
- Each Dockerfile instruction creates a new layer.
- Layers are cached and reusable.
- Layering improves:
  - Build speed
  - Storage efficiency

## 3. Docker Container
- A container is a running instance of an image.
- Containers are isolated using:
  - Namespaces (process, network, filesystem isolation)
  - cgroups (CPU and memory resource limits)
- Containers are:
  - Ephemeral
  - Portable
  - Environment-consistent

## 4. Docker Registry
- A Docker Registry stores and distributes images.
- Examples include:
  - Docker Hub
  - AWS ECR
- Enables:
  - Build once, deploy everywhere
  - Consistent environments (dev, staging, prod)
  - Elimination of environment mismatch issues

# Kubernetes — Core Concepts

## 1. What is Kubernetes
- Kubernetes is a container orchestration platform.
- Docker runs containers on a single machine.
- Kubernetes manages containers across a cluster of machines.
- Provides:
  - Scheduling
  - Auto-scaling
  - Self-healing
  - Rolling updates

## 2. Cluster Architecture
A Kubernetes cluster consists of a Control Plane and Worker Nodes.

### Control Plane
- Responsible for global decision-making and cluster state management.
- Core components:
  - API Server — central interface for cluster operations
  - etcd — distributed key-value store holding cluster state
  - Scheduler — assigns Pods to nodes
  - Controller Manager — reconciles actual state with desired state

### Worker Nodes
- Run application workloads.
- Execute Pods and containers.

## 3. Pod
- The smallest deployable unit in Kubernetes.
- A Pod may contain:
  - One container
  - Multiple tightly coupled containers
- Containers in the same Pod share:
  - Network namespace (same IP)
  - Storage volumes
- Pods are ephemeral.
- If a Pod fails, Kubernetes creates a replacement.

## 4. Deployment
- A Deployment defines the desired state for a group of identical Pods.
- Internally manages a ReplicaSet.
- Ensures the specified number of replicas are always running.
- Supports:
  - Rolling updates
  - Zero-downtime deployment
  - Rollback to previous versions

## 5. Service
- A Service provides stable networking and load balancing.
- Pod IPs change when Pods are replaced.
- A Service exposes:
  - Stable DNS name
  - Stable virtual IP
- Common Service types:
  - ClusterIP — internal cluster access
  - NodePort — exposed via node IP and port
  - LoadBalancer — external load balancer (cloud)

## 6. Declarative Model
- Kubernetes follows a declarative configuration model.
- Desired state is defined in YAML files.
- Kubernetes continuously reconciles:
  - Actual state toward desired state.
- Automatic behaviors include:
  - Restarting failed containers
  - Rescheduling Pods
  - Maintaining replica count
  - Scaling as configured
