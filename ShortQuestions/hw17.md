## Testing related Concepts
### 1. Unit Testing 
**Definition**<br>
Unit Testing verifies a single unit of code, such as a method or class, in isolation

**Purpose**<br>
To ensure that individual business logic works correctly

**Example**<br>
Testing a discount calculation method:
```java
public double calculateDiscount(double price, double rate) {
    return price * rate;
}
```
Test case verifies that calculateDiscount(100, 0.1) returns 10

**Key Point**<br>
Focuses only on one small piece of code and usually mocks dependencies

### 2. Functional Testing
**Definition**<br>
Functional Testing verifies whether a feature works according to business requirements from a user perspective

**Purpose**<br>
To ensure that the system behaves correctly based on requirements

**Example**<br>
Testing login feature:<br>
User enters correct username and password and successfully logs in

**Key Point**<br>
Focuses on feature correctness, not internal implementation

### 3. Integration Testing
**Definition**<br>
Integration Testing verifies the interaction between multiple components or modules

**Purpose**<br>
To ensure collaboration between modules works correctly

**Example**<br>
Testing Service layer calling Repository layer to fetch data from database

**Key Point**<br>
Unlike Unit Testing, it does not isolate components. It tests real interaction

### 4. Regression Testing 
**Definition**<br>
Regression Testing re-runs existing tests after code changes

**Purpose**<br>
To ensure that new changes do not break existing functionality

**Example**<br>
After adding a new payment method, re-run all checkout-related tests

**Key Point**<br>
Focuses on stability after modifications

### 5. Smoke Testing 
**Definition**<br>
Smoke Testing verifies basic functionality of a newly built application

**Purpose**<br>
To quickly check if the system is stable enough for further testing

**Example**<br>
After deployment, verify application starts, login works, main page loads

**Key Point**<br>
It is shallow and broad, usually part of CI/CD pipeline.

### 6. Performance Testing 
**Definition**<br>
Performance Testing measures system response time and throughput under expected workload

**Purpose**<br>
To verify efficiency and speed

**Example**<br>
System handles 500 requests per second with average response time under 200ms

**Key Point**<br>
Tests system performance under normal conditions

### 7. Stress Testing 
**Definition**<br>
Stress Testing evaluates system behavior under extreme workload

**Purpose**<br>
To test system stability and failure handling

**Example**<br>
System receives 5000 requests per second to check if it crashes

**Key Point**<br>
Unlike Performance Testing, workload exceeds normal limits

### 8. A/B Testing 
**Definition**<br>
A/B Testing compares two versions of a feature to determine which performs better

**Purpose**<br>
To optimize user experience or business metrics

**Example**<br>
Version A shows blue button, Version B shows red button<br>
Measure which version increases conversion rate

**Key Point**<br>
Focuses on real user behavior and business outcome, not code correctness

### 9. End-to-End Testing 
**Definition**<br>
End-to-End Testing verifies the complete workflow of an application

**Purpose**<br>
To ensure the entire system works from start to finish

**Example**<br>
User registers, logs in, places order, completes payment successfully

**Key Point**<br>
Tests full system flow including frontend, backend, database

### 10. User Acceptance Testing
**Definition**<br>
User Acceptance Testing is performed by end users to validate the system meets their needs

**Purpose**<br>
To confirm the software is ready for production use

**Example**<br>
Business users test reporting system before official launch

**Key Point**<br>
Performed by real users, not developers

### Extra: Comparison
**Unit vs Integration**
- Unit tests single component
- Integration tests collaboration between components

**Functional vs End-to-End**
- Functional tests a feature
- End-to-End tests full workflow

**Performance vs Stress**
- Performance tests normal workload
- Stress tests extreme workload

**Smoke vs Regression**
- Smoke tests basic functionality after deployment
- Regression tests verify no old features are broken

**A/B vs Other**
- A/B focuses on business metrics
- Others focus on technical correctness

## Environment related Concepts
### 1. Development
**Definition**<br>
Development environment is where developers write and test their own code

**Purpose**<br>
To build new features and fix bugs safely

**Example**<br>
A developer runs Spring Boot application locally and tests API using Postman

**Key Point**
- Used by developers only
- Data is usually fake or local
- Code may be unstable

### 2. QA (Quality Assurance)
**Definition**<br>
QA environment is used for testing by QA engineers

**Purpose**<br>
To verify features before moving to higher environments

**Example**<br>
QA team tests login, payment, and user registration after a new sprint release

**Key Point**
- Separate from Development
- More stable than Dev
- Used for functional and regression testing

### 3. Pre-prod/Staging
**Definition**<br>
Pre-production or Staging environment closely mirrors Production

**Purpose**<br>
To validate system behavior in a production-like setup before official release

**Example**<br>
Testing real deployment process, database configuration, and load balancing before release

**Key Point**
- Same configuration as Production
- Final verification step
- Used for smoke testing and final checks

### 4. Production
**Definition**<br>
Production environment is the live system used by real users

**Purpose**<br>
To serve actual customers

**Example**<br>
Users placing real orders on an e-commerce website

**Key Point**
- Real users and real data
- Highest stability requirement
- Any issue affects customers

### Extra: Comparison
**Development vs QA**
- Development is for coding and self-testing
- QA is for formal testing by testers

**QA vs Staging**
- QA tests feature correctness
- Staging validates release readiness

**Staging vs Production**
- Staging simulates real environment
- Production serves real users
